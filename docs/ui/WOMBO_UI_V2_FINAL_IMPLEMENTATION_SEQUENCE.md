## 3. Per-batch review evidence

For each changed family, record source revision, device, logical width, font scale, language, state/fixture provenance and exact screenshot path. Capture top and lower viewport where needed; do not stitch unrelated states or make fake live screenshots. Preserve reference PNGs/manifest. Compare **composition, typography, icon circles, landscape fade, card surfaces and CTA/nav treatment** to the closest user mockup, and compare **fields, warnings, actions and state meaning** to the mapped functional image.

Required widths: 320, 360, ~393 and 412 dp, at default and 200% text. Dutch and English. Include long source names, absent optional data, multiple same-day occurrences, keyboard visible, system gesture inset, modal/sheet focus, reduced motion and TalkBack. Do not accept cropped controls because the reference raster cropped them. A taller page is acceptable; smaller accessibility type is not.

A future implementation batch passes only when both mockup fidelity and functional parity are reviewed. If the date-grid alternative or vector assets need iteration, change the shared visual primitive and recheck its consumers; do not create unrelated per-screen exceptions. If a product decision is missing, keep that capability unavailable and report it.
