## Missing deterministic metadata

The source supplies ID, sport, title, RPE pair, expected zone, total, multiplier,
zone totals, P, ordered segments and focus. These do **not** define all domain
fields or selection behavior. The current domain requires nonempty phase tags,
whole-workout intensity bucket, capabilities/fallback policy, selection flags,
immutable identities/versions, description and per-segment scalar RPE.

- Joren must approve bucket and phase tags, particularly all mixed intervals.
  Existing base/recovery/taper filters require only Z1/Z2 and a low bucket.
  Build 1–3 excludes Z5; build 4 conditionally requires affordable safe Z5 work.
  Do not derive these new rows' eligibility from the old IDs' generic tags.
- Expected Zone is a focus zone, not an assertion that every interval uses it.
  Whole-workout 80/20 buckets and execution distributions are different metadata.
  No title/focus-based physiological rule is introduced.
- Mixed rows give session RPE 7–8 or 9–10, while Z2 intervals need their own
  approved RPE guidance. Current aggregate-range validation must be respected;
  do not widen source fields silently or assign hard-block RPE to recovery.
- Confirm execution capability and unvalidated fallback compatibility, including
  whether numeric-zone projection or RPE guidance is intended. New Session-RPE
  mapping does not change existing calibration or legacy prescriptions.
- Source event specificity is absent. Existing event words are descriptive, not
  hard eligibility rules, so absence alone is not a new failure condition. Any
  new event-specific filter needs its own product decision; do not invent one.

The existing CSV generator cannot ingest this workbook unchanged: it expects
`ID`, `Tijd n`/`Zone n`, `Emmer (80/20)` and integer source TSS. Its source UUID
helper parses the second hyphen-separated token as a number; that token is `RUN`
in `TR-RUN-001`, so reusing it would fail. A future explicitly reviewed adapter
must preserve decimals and the new namespace, rather than truncate TSS, rename
IDs to make the old helper work or merge on titles. No adapter is implemented.

## Proposed common intake envelope

Accept the future files only as separately attributable sources, with a declared
sport-specific schema. Do not require identical headers, durations, coefficients
or measurement method just because running used them.

| Contract group | Required normalized information / rejection rule |
| --- | --- |
| Immutable source | Original bytes, filename, SHA-256, byte count, delivered/accepted revision and owner record; replacement bytes are a new source revision |
| Workbook scope | Every worksheet/state, used extent, every row including trailing/hidden rows, merged ranges, cell type/value/raw numeric lexeme/formula/cache/format; classify notes and records explicitly |
| Stable identity | Source catalog ID+version, sport, stable source workout ID, template UUID/key/version mapping and replacement relation; reject duplicate/version collision and unexplained identity reuse |
| Measures | Explicit units and canonical duration/distance basis; reject nonfinite/negative values and incompatible timed/distance-only mixtures; absent is not zero |
| Ordered prescription | Contiguous sequence, supported explicit zone/target, positive segment measure, original rest/warm-up/cooldown semantics, complete totals and per-zone allocation agreement |
| RPE/guidance | Canonical 1–10 endpoints, range ordering, explicit mapping version and per-segment targets compatible with template validation; unknown mapping blocks normalization |
| Selection | Approved whole-workout low/high bucket, phase tags, capabilities, fallback compatibility, auto/swipe/explicit-only flags; absent fields block activation |
| Private expected load | Original P lexeme, declared method/ruleset, complete coefficient/IF provenance, multiplier stage, precision/rounding, independent expected result and accepted discrepancy decision |
| Approved occurrence | Future exact plan/revision/occurrence/template/source/P/T/zone/method/version snapshot; source row alone never constitutes athlete approval |

   inspect every populated, hidden and trailing row. Inspect formula text and

   source. Check every required field and type, duplicate/missing IDs, sport and

   Report counts independently, including all rows outside the expected ID range.
3. Parse the **entire** ordered syntax, preserving order, repetitions, recovery,
   rests and measures; reject unparsed tokens or ambiguous repetitions. Do not
   infer missing warm-up/cooldown. Compare segment total to workout total and,
   when supplied, each zone aggregate. Do not treat a distance token `m` as
   minutes without the source-specific grammar/unit declaration.
4. Check every RPE endpoint and each ordered target under the declared mapping
   version. Report session-versus-segment mismatches separately. Validate the
   approved whole-workout bucket without inferring it from maximum zone or title.
   Confirm training focus as source text; do not certify efficacy from a label.
5. Reconcile each row's private source expected load against the **actual supported
   engine method for that source/sport**, separately reporting retained source P
   and independent zone-minute calculations where measures allow them. Trace all
   formulas, anchors, coefficients and multiplier placement. Do not copy running
   1.15 or coefficients into cycling/swimming. Show raw difference and presentation
   difference, cause evidence, proposed resolution and required acceptance.
6. Apply RPE-fallback structure checks to every explicit segment, not zone totals
   alone. Then separately verify supported occurrence method/version, exact P/T,
   occurrence identity, actual confirmed A and source hierarchy. Exclude mixed,
   protocol/RPE-only, unknown and unconfirmed cases from full eligibility.
7. Produce exact old/new ID and ordered-execution comparisons; distinguish
   structural equivalence from RPE/load/phase/provenance equivalence. Require
   an owner-approved replacement/deprecation table; preserve immutable history.
8. Re-evaluate deterministic phase/candidate coverage, repeats, 24-occurrence
   bound, date availability, anti-stack constraints, low-only injury restrictions,
   recovery/taper, target fit and warning/error behavior without changing rules.
   Report nearest-fit results and missing capabilities, not just numeric capacity.
9. Check private-load boundaries recursively across DTOs/OpenAPI, UI/accessibility,
   errors/logs/analytics/LLM facts. Identity remains verified-token-derived;
   service keys remain server-side. Preserve optimistic concurrency, idempotency,

10. Rehash the original file at completion; validate report row counts against the
