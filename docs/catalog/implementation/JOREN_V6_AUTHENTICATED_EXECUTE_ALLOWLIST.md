# Proposed authenticated EXECUTE allowlist

17 November 2026. **LOCAL PROPOSAL; OWNER SIGNATURE-LEVEL APPROVAL REQUIRED. Production execution remains prohibited.**

The exact [machine allowlist](blocker-resolution-20261117/authenticated-execute-allowlist.json) contains **13 authenticated EXECUTE exceptions**, with no anonymous exception, grant option, generated-plan writer or private-table grant. Approval of this document is distinct from approval to execute a particular production bundle.

Every listed read could theoretically be redesigned around a service credential. That would require new server owner plumbing and would remove useful caller-token boundaries. The proposal retains the verified owner-scoped contracts and denies service writers to ordinary athletes. It does not treat every SECURITY DEFINER warning as a vulnerability or every private function as inaccessible.

## Forward correction C2

`20261116231107_v6_reviewed_privilege_closure.sql` reasserts only the reviewed grants, removes unnecessary catalog Dxtm privileges and narrows the application's future-table defaults. It also fixes a real SQL NULL-CAS bypass in `save_frequency_preferences`: `current_revision <> NULL` did not reject the request. The original behavior was reproduced against PostgreSQL; the corrected RPC rejects it while valid storage, exact replay and stale rejection pass. This is a concurrency correction, not a frequency or physiological rule change.

C2 is appended inside G3, so the incomplete new preference precondition is never an externally committed intermediate state. It does not rewrite an accepted migration, enroll an operator/reviewer, grant frequency role membership, calculate load, or activate a source.
