There is no location, camera, photo, notification or advertising-ID permission in this source manifest. Manifest merger and the final AAB still require inspection. No app camera/photo picker, device file upload, device calendar sync, push registration, payments, advertising analytics, crash SDK or controlled WebView was found. Polar OAuth opens an external browser, whose cookies are governed by Polar/browser behavior. The optional web target stores language in browser local storage; no app cookie code was found.

Output 4 — account deletion assessment and exact work

Current answer: No. The app supports signUp but Profile has only sign-out; the API router has no deletion request/operation; no public deletion webpage or contact flow is in this repo. A database cascade alone is not a user-accessible deletion mechanism. Google Play requires both an in-app initiation path and a web resource that works after uninstall. Signing out and Polar disconnect are insufficient.

  1. Choose and publish an operator identity, privacy email and a public, non-geofenced Wombo deletion page. The page must let a former user submit a request without reinstalling the app; a functioning email/form can be used. Add its URL to Play Console.
  2. Add a clearly labelled Delete account and data action in Profile. Require an authenticated session, an explicit confirmation and an identity-safe deletion request/operation. Document status and expected processing time. Do not make sign-out appear to be deletion.
  3. Implement a trusted backend workflow to revoke/stop Polar access, remove private FIT storage objects, remove the Supabase Auth user with administrative credentials, and verify cascades across public/private owner tables. Make it idempotent and recoverable if external revocation or storage deletion fails. Clear local secure-storage keys and sign out after success.
  4. Fix the Pioneer FK lifecycle in a forward-only migration: private.pioneer_access_codes.redemption_id → public.pioneer_access_redemptions.id ON DELETE RESTRICT can block deletion of a redeemed athlete; redeemed_by_athlete_id ON DELETE SET NULL also conflicts with its “redemption complete” check. Define whether the code/attempt ledger is erased or de-identified, then test real redeemed and unsuccessful-code accounts. Do not rewrite the applied migration.
  5. Test Auth deletion against every owner table and Supabase Storage, including connected/disconnected Polar users, FIT files, Pioneer redemption, pending plans and check-ins. Verify what remains in backups/logs, define exceptions and response deadlines, and provide a manual support route for failed requests. Deleting the public.activity_files row does not itself delete storage.objects.
  6. Only then mark “users can request deletion” and “account deletion available” in Data safety, link the page in Play Console, add the privacy-policy link/text inside the app, and confirm the policy's deletion language matches the actual process.
